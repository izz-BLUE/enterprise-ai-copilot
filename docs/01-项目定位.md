本项目是一套企业级 RAG + Agent 业务流程辅助平台，采用 Java + Python 双服务架构，Java 侧负责企业业务系统能力，Python 侧负责 RAG、Agent、Tool Calling 和大模型编排能力。

# 项目定位

本项目不是单纯的知识库问答 Demo，而是一套面向企业内部业务场景的 AI Copilot 平台。

项目采用 Java + Python 双服务架构：

- Java 侧负责企业级业务系统能力，包括用户权限、知识库管理、文档管理、文档版本、审计日志、业务流程模板等。
- Python 侧负责 AI 能力，包括 RAG、Agent、Tool Calling、Prompt 编排、低置信度拒答和引用来源返回。

项目支持多个业务域：

1. 银行业务制度问答
2. 企业 HR / 行政制度问答
3. IT 运维知识库问答
4. 智能客服工单辅助

项目目标是证明开发者具备将大模型能力落地到企业业务系统中的工程能力。



 **为什么聊天接口必须走 Java？** 

 问题 1：为什么前端不直接调 Python？ 

前端请求应该先进入 Java 主系统，因为 Java 层负责企业业务系统的统一入口，包括用户认证、权限校验、参数校验、日志审计、请求追踪和业务路由。Python Agent 服务只作为内部 AI 能力服务，由 Java 调用，不直接暴露给前端。



 问题 2：为什么聊天接口放 Python？ 

聊天接口最终会演变成大模型调用、RAG 检索、Prompt 编排和 Agent 工具调用入口。Python 生态在 LangChain、LangGraph、LlamaIndex、Embedding、向量检索等方面更成熟，所以 AI 编排逻辑放在 Python 服务中更合适。



 问题 3：Java 未来负责什么？ 

Java 负责“谁能用 AI、用哪个知识库、问题怎么记录、结果怎么审计、业务流程怎么串起来”。
Python 负责“怎么调用模型、怎么检索、怎么组织 Prompt、怎么生成答案”。



### 总结

 java 不负责 AI 编排核心逻辑，但 Java 会负责 AI 能力的业务接入。
