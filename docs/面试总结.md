### 标准回答

```

```

# 二、Prompt 工程类（Day4 核心）

------

## 4. system prompt 和 user message 有什么区别？

### 标准回答

```
system prompt 用于定义模型角色、行为边界和回答规则。user message 是用户当前的具体问题。模型会在 system prompt 的约束下处理 user message。
```

------

## 5. 为什么企业 AI 不能让模型自由发挥？

### 标准回答

```
大模型存在幻觉和不确定性。企业场景涉及制度、流程、合规和审计，如果模型自由生成，可能伪造制度或给出错误流程。因此需要通过：system prompt、知识库、拒答机制、引用来源等方式限制模型行为。
```

------

### 真正考察

```
你是否理解：企业 AI≠聊天机器人
```

。

------

## 6. Prompt 的本质是什么？

### 标准回答

```
Prompt 本质上是对模型行为的约束和引导。不仅是“让 AI 更聪明”，更重要的是：定义角色、限制回答范围、控制输出风格、降低幻觉风险。
```

# 三、异常处理与工程类（Day4 高含金量）

------

## 7. 为什么 AI 服务需要异常处理？

### 标准回答

```
AI 服务属于外部依赖，可能出现：网络超时、API Key 错误、模型不可用、余额不足等问题。因此需要在 Python 与 Java 两层增加异常兜底，避免整个接口直接崩溃。
```

------

## 8. 为什么返回统一响应结构？

### 标准回答

```
统一响应结构便于前端和调用方统一处理结果。当前项目统一返回：successanswermodeltraceId即使 AI 服务异常，调用方也能正常解析 JSON。
```

------

## 9. traceId 有什么作用？

### 标准回答

```
traceId 用于请求链路追踪。当系统出现问题时，可以根据 traceId 在 Java、Python、日志系统中定位同一次请求。
```

# 四、HTTP / DTO / 微服务基础（你已经踩坑了）

------

## 10. 为什么会出现 FastAPI 422？

### 标准回答

```
FastAPI 的 422 通常表示请求体或字段校验失败。本次问题原因包括：- Java 与 Python DTO 字段不一致- Python 未正确解析请求体- Content-Type 不匹配
```

------

## 11. 为什么 Java 与 Python DTO 字段必须一致？

### 标准回答

```
因为 Java 与 Python 之间通过 JSON 通信。如果字段名不一致，会导致：字段缺失、反序列化失败、422 校验异常等问题。
```

------

## 12. RestTemplate 是什么？

### 标准回答

```
RestTemplate 是 Spring 提供的 HTTP 客户端。用于在 Java 中发送 HTTP 请求，实现服务之间的通信。
```
