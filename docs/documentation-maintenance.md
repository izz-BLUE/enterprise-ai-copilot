# 文档维护规则

本文是长期规则，不是某次审计或发布报告。

## 文档类别

- **当前态文档**：README、架构、API、部署、质量、RAG、业务动作、Memory、性能和路线图。它们解释当前系统，必须以代码、测试、配置和部署文件校准。
- **私人学习与面试资料**：不属于公开文档体系，由本地忽略规则管理，不作为公开文档入口或运行依赖。
- **历史快照**：`docs/releases/`。描述发布当时的事实，除链接损坏或明显排版问题外，不用当前状态“现代化”改写。
- **协作入口**：`AGENTS.md`、`CLAUDE.md`、`CONTRIBUTING.md`、`SECURITY.md` 和各组件 README。它们按各自职责维护，不能当作普通阶段报告清理。

## 新增 Markdown 的条件

只有在以下情况之一成立时才新增永久 Markdown：存在新的稳定读者和职责、需要保留正式发布快照，或需要记录对未来设计仍有价值的独立技术决策。新增前先搜索现有文档，优先更新或合并已有 canonical source。

以下内容默认不再创建永久 Markdown：单次 Bug 修复报告、Coding Agent Delivery Report、单次 Audit 报告、临时 TODO、migration plan、rollout checklist 和 commit 总结。它们应进入 Git commit、PR 或 issue。

## 防止事实漂移

- 先查当前 HEAD 的生产代码和测试，再查配置、migration、部署、CI 和 eval；Git history 只用于解释历史，Markdown 最后校准。
- 能引用配置项、代码路径或可复现命令时，不在多份文档中复制易变数字。测试数、脚本行数、worker 批量和运行时状态默认不作为长期固定事实。
- 当前态文档只保留理解架构必要的少量数字，并标明来源；运行结果必须说明时间点、环境和是否为 CI 门禁。
- 代码与文档冲突时修改文档，不通过修改生产代码迎合旧表述。无法证明的公网状态、真实外部系统或生产能力必须明确标为未验证。
- 删除、移动或合并文档前，全仓搜索 Markdown 链接、README、`AGENTS.md`、`CLAUDE.md`、脚本、CI 和发布记录；完成后再验证无死链接和残留引用。
