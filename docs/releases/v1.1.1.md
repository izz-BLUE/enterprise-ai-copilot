## Fix

- Prevent duplicate reconciliation of expired HITL continuations.
- Add a persisted reconciliation delivery state separate from the business action status.
- Atomically mark an expired HITL continuation as `RECONCILED` only after resume succeeds.
- Keep resume failures retryable and fail-closed.
- Do not replay an expired HITL that has already been safely closed.
- Allow a terminal `ai_task_memory` row to explicitly start a new Expense clarification cycle.
- Preserve the safety rule that ordinary terminal Memory upsert cannot reactivate a terminal row.
- Keep Java as the HITL and Memory lifecycle authority.
- Python production code was not modified.

This release is limited to HITL / Memory lifecycle maintenance.

## Rollback Note

- `ROLLBACK_REPLAY_RISK`: `HIGH`

The old `v1.1.0` Java runtime does not understand the new HITL reconciliation
delivery state. Rolling back directly to the old Java runtime could rescan
historical expired HITL rows and trigger the old resume path.

The V13 schema is structurally compatible with the old Java runtime, but a
lifecycle-behavior rollback is not risk-free. No automatic rollback procedure
is defined by this release document.
