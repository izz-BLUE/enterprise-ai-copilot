# v0.4.0——有界并发与受控负载验证

v0.4.0 为 Enterprise AI Copilot 增加面向小规格单机部署的有界并发保护、分层压测和一致的公网过载响应。目标是让突发请求快速、可解释地降级，而不是宣称高并发或生产级 SLA。

## 主要变更

- Java `PythonAgentBulkhead`：限制 Java → Python 的在途 AI 请求，默认 3 个并发槽，最多等待 500ms
- Python `RequestConcurrencyLimiter`：限制检索、Agent 和 LLM 执行入口，默认 3 个并发槽，最多等待 500ms
- 递增超时预算：Python LLM 30s、Java 下游读取 40s、Nginx 上游 45s
- 过载快速失败：应用层返回 HTTP 429、`Retry-After: 1`、`success=false` 和 traceId
- 公网入口限流：Nginx 2 req/s、burst 5，429 使用前端可解析的 JSON，并隐藏具体 Nginx 版本
- 健康接口增加不含敏感信息的并发快照：上限、活跃数、可用槽、拒绝数和排队超时
- GitHub Actions 增加 Java/Python 并发单元测试
- 新增四个 k6 场景和对应停止条件

## 目标服务器验收摘要

测试环境为 3.3 GiB 共享服务器；Java/Python 容器内存限制均为 512 MiB，并发槽均为 3。

| 层级 | 场景 | 结果 |
|------|------|------|
| L1 | localhost 健康接口，2 VU / 2 分钟 | 560,336 次请求，失败 0，P95 0.468 ms |
| L2 | Safety Guard，3 VU / 30 次 | 30/30 确定性拒答，5xx 0，P95 117 ms |
| L3 | AI 过载，6 VU / 12 次 | 4 次成功、8 次 429、5xx 0，P95 1.67 s |
| L4 | 公网 Nginx 限流，10 req/s / 5 秒 | 15 次 200、36 次 429、5xx 0，P95 4.02 ms，P99 4.13 ms |

L3 中 Java 拒绝计数与 k6 的 8 次 429 完全一致，证明配置为 3 的并发边界能够生效。L4 的 JSON、`Retry-After`、traceId 和版本隐藏契约全部通过。Java/Python 无重启、无 OOM，其他同机服务保持健康。

## 结果边界

- L1 是 localhost 健康接口紧循环，不能表述为公网 QPS 或业务吞吐量
- L3 证明并发保护有效，不代表系统最大容量
- L4 验证单客户端 IP 的入口限流，不代表外部互联网延迟或多客户端容量
- 测试持续时间较短，不能替代长时间 Soak、分布式压测、高可用或生产 SLA
- 当前仍是个人工程实践项目和公网 Demo，不是生产级 RAG 平台

## 升级说明

- 无数据库迁移
- Java/Python 镜像需要包含 v0.4.0 并发实现
- Compose 需要配置 Java/Python 并发上限与超时预算
- Nginx 归档配置包含 JSON 429、`Retry-After` 和 `server_tokens off`
- 生产 Secret 继续通过未跟踪的 `.env` 注入，不得写入镜像、前端或 Git

## 回滚

- Git：回滚到 v0.3.3
- Java/Python：恢复 v0.3.3 对应镜像和 Compose
- Nginx：恢复变更前配置并先执行 `nginx -t`，再平滑 reload；若单文件只读 bind mount 因 inode 替换未更新，需要在维护窗口重启共享 Nginx 容器
