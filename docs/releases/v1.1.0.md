## Major changes

### 1. Expense reason semantic extraction

- `reason` is extracted by the existing Planner LLM structured output.
- There is no independent reason-field LLM call.
- Regex extraction was removed.
- The trip-purpose fallback was removed.

### 2. Durable continuation

- The extracted reason is frozen within the request scope.
- Missing reason is represented by `waiting_for=reason`.
- `original_request` is write-once and preserved across continuation.
- Java owns task-critical continuation persistence.
- Memory LLM failure does not block critical continuation.

### 3. Expense prerequisites

- The selected trip defines the invoice scope.
- Cross-trip invoices fail closed.
- All selected-trip invoices must be verified before creating a Proposal.
- `action_proposal != null` is the completion signal for a real Proposal.
- Clarification is not treated as completed Proposal output.

### 4. Legal Action Masking

- The Planner owns the next Tool selection.
- The Planner sees only currently legal Expense actions.
- Invoice order remains Planner-selectable.
- Fixed state machine: `NO`.
- Planner override: `NO`.
- Automatic Tool chaining: `NO`.

### 5. PostgreSQL checkpoint integration

- Integration fixtures were aligned with the reason-first and prerequisite contracts.
- PostgreSQL checkpoint suite: `34 passed`.
